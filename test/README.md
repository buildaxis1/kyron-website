# Testing with Playwright

This directory contains Playwright integration tests for the HealthClinic AI application.

## Setup

1. Install Playwright dependencies:

```bash
npm install
npx playwright install
```

2. Make sure your database is set up and running:

```bash
npm run db:migrate
```

3. Ensure your environment variables are properly configured.

## Running Tests

### Run all Playwright tests:

```bash
npm run test:playwright
```

### Run only integration tests:

```bash
npm run test:integration
```

### Run tests in headed mode (with browser UI):

```bash
npx playwright test --headed
```

### Run tests in debug mode:

```bash
npx playwright test --debug
```

## Test Structure

### Integration Tests (`test/updates/`)

#### `update-encounter.test.ts`

- Tests the `updateEncounterDetails` tRPC procedure directly
- Covers CRUD operations for encounters, patients, physicians, facilities, and insurance
- Tests data validation and error handling
- Tests encryption/decryption of sensitive data

#### `update-encounter-ui.test.ts`

- Tests the encounter update functionality through API calls
- Tests form validation and error handling
- Tests various field updates (CPT codes, ICD codes, insurance, dates, etc.)
- Can be extended to test actual UI interactions

## Test Features

### Database Integration

- Uses real Prisma client for database operations
- Creates and cleans up test data automatically
- Tests actual database transactions and constraints

### Comprehensive Coverage

- Patient information updates
- Physician information updates
- Facility information updates
- Encounter details updates
- Insurance management (multiple insurances)
- CPT and ICD code handling
- Date field validation
- Error handling and validation

### Data Encryption Testing

- Verifies that sensitive data is properly encrypted

## Configuration

The tests are configured in `playwright.config.ts` with:

- Test directory: `./test`
- Parallel execution enabled
- HTML reporter for test results
- Retry logic for CI environments

## Best Practices

1. **Data Cleanup**: Each test suite properly cleans up test data to avoid conflicts
2. **Isolation**: Tests are isolated and don't depend on each other
3. **Real Database**: Tests use actual database operations for realistic testing
4. **Error Testing**: Includes negative test cases for error handling
5. **Comprehensive Coverage**: Tests cover all major functionality paths

## Extending Tests

To add new tests:

1. Create new test files in the appropriate subdirectory
2. Follow the existing pattern for setup/teardown
3. Use the Playwright test API (`test.describe`, `test`, `expect`)
4. Include both positive and negative test cases
5. Ensure proper data cleanup

## Troubleshooting

- If tests fail due to database issues, ensure your database is running and migrations are up to date
- Check that environment variables are properly set
- Verify that the test user ID exists in your system
- Check the HTML report generated by Playwright for detailed failure information
